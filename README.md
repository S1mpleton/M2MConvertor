# M2MConvertor

Учебное приложение комплекса M2M. Рабочая ветка — `Codex`.
Варианты загружаются из зашифрованного `.m2m`, экспортированного
**M2MTools, ветка `Lite`**. Архив содержит реакцию, отдельные количества
состояний и сигналов Мура/Мили и изображение задания, без эталонного автомата.

## Работа с вариантом

- На начальном экране выбираются архив и номер варианта.
- Доступно **Мура → Мили**. Варианты Мили → Мура видны с отметкой
  «в разработке», но открыть их нельзя, включая сохранённые работы.
- После проверки количеств исходного автомата пользователь последовательно
  заполняет таблицу, матрицу и граф Мура, затем таблицу, матрицу и граф Мили.
- Состояния генерируются как `a0, a1, …` отдельно по количеству Мура и Мили
  из варианта. Начальное состояние всегда `a0`, его нельзя выбирать или переименовывать.
- Входные сигналы вводятся пользователем: `x0`…`x9`, разные, через запятую.
  Их число должно совпадать с количеством для редактируемого автомата.
- Выходы `y0`…`y9` вводятся в ячейках/подписях через запятую, без повторов.
  Алфавит выходов собирается из введённых данных; число различных выходов
  сверяется с количеством соответствующего автомата в варианте.
- В таблице Мура первая строка — выходы состояний, остальные — следующие
  состояния. В таблице Мили переход записывается как `a1 / y0,y3`.
- Матрица имеет размер N×N и заголовки `a0`…`a(N−1)` по обеим осям:
  строка — исходное состояние, столбец — конечное. Метки нескольких дуг
  разделяются `;`. Мура: `x1; x2`; Мили: `x1 / y0; x2 / -`.
- Рядом с матрицей Мура находится независимая таблица из двух столбцов:
  фиксированное состояние и вводимые пользователем выходы. Выходы не
  копируются из принятой таблицы. Принятая таблица сверху служит справкой.
- Пустая ячейка или `-` в переходах означает отсутствие перехода;
  пустой выход или `-` означает отсутствие выходного сигнала.
- Граф остаётся интерактивным: создание/удаление вершины,
  перемещение, Ctrl+щелчок для дуги (в том числе петли), двойной щелчок
  для редактирования выходов Мура или метки дуги, ручной изгиб,
  Backspace/Delete. Создаются только состояния варианта; после удаления
  повторно используется освободившееся имя. Выходы вершин Мура вводятся заново.
- Палитра и оформление элементов управления наследуются от ОС.

## Критерий проверки

Все шесть представлений независимо проверяются `ReactionChecker` по одной
реакции из архива. Порядок тактов при чтении сохраняется, включая повторы
входов и пустые выходы; пропускать, сортировать или объединять такты нельзя.
Порядок записанных выходов сохраняется в данных, но сравниваются множества
одновременно выдаваемых сигналов (`y3,y0` и `y0,y3` равнозначны).
Имена сигналов сравниваются точно: переименование входов/выходов не допускается.

Перед первым тактом автомат находится в `a0`. На каждом такте сначала
выполняется переход по входному сигналу. Для **Мура** сравнивается выход
**достигнутого состояния**, для **Мили** — выход перехода. Выход Мура в `a0`
до первого входа не добавляет отдельного такта. Это сохраняет принятую
ранее в приложении семантику преобразования Мура → Мили.

Отсутствующий переход, неверный выход, недетерминированные переходы,
неверные имена или количества приводят к отклонению. При расхождении
реакции сообщение указывает первый неверный такт, состояние, вход и выходы.
Не требуется изоморфизм с конкретной конструкцией автомата.

**Предел проверки:** одна конечная реакция не определяет полный автомат.
Принятый ответ совпадает с заданной реакцией; это не доказательство
эквивалентности на всех возможных входных последовательностях.
Непосещённые реакцией переходы проверяются структурно, но их поведение
нельзя сверить с отсутствующим эталоном. В интерфейсе и HTML-отчёте
используется именно формулировка о совпадении реакции.

## Форматы и ограничения

- `.m2m`: контейнер `M2MLITE1`, AES-256-GCM, PBKDF2-HMAC-SHA256,
  200 000 итераций, совместимый с текущим экспортом M2MTools.
  В JSON — `format: M2MToolsLite`, `version: 1`, `variants`, `mealy`,
  `moore`, упорядоченный `reaction`, `image { fileName, data }`.
- Старые архивы `M2MTOOLS2`, содержащие полный автомат, не открываются;
  требуется новый экспорт из M2MTools.
- Прогресс сохраняется в едином `.m2mwork`, версия **2**. Сохраняются
  таблицы, отдельные выходы матрицы, подписи, позиции и изгибы графа.
  При восстановлении все отметки «принято» перепроверяются по реакции.
  Работы версии 1 относятся к прежней модели задания и не поддерживаются.
- Изображение из архива проверяется на корректность; максимум — 10 МБ.
- Текущий редактор матриц ограничен 250 000 ячейками (до 500 состояний)
  для защиты от чрезмерного выделения памяти. При превышении показано
  сообщение вместо создания таблицы.

## Структура и сборка

- `M2MConvertorCore`: модель автомата/варианта, проверка реакции, чтение
  архива и хранение прогресса. Алгоритмы преобразования, эквивалентности
  и изоморфизма сохранены как отдельные модули, но в новый критерий не входят.
- `M2MConvertorUi`: главное окно, таблица/матрица и интерактивный граф.
- `M2MConvertor`: запускаемое приложение.
- `M2MConvertorTests`, `M2MConvertorGuiSmoke`: тесты того же кода,
  который используется приложением.

Требуются CMake 3.19+, C++17, Qt 6.5+ (Core, Gui, Widgets, LinguistTools,
для тестов также Test) и OpenSSL 1.1.1+.

```bash
cmake -S . -B build -G Ninja -DBUILD_TESTING=ON
cmake --build build
ctest --test-dir build --output-on-failure
```

Тесты охватывают чтение/аутентификацию архива, сохранение порядка реакции,
реакцию обоих типов автоматов, ошибки отдельных тактов, блокировку Мили →
Мура, все шесть редакторов, восстановление прогресса и интерактивный граф.
Для проверки реального экспорта M2MTools тестовая программа также принимает
путь к тестовому `.m2m` (вариант №7 из `tests/archivefixture.h`).
